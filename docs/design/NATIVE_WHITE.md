# A Native White 적용

승인 디자인은 2026-10-18 패키지의 **A Native White**다. `START_HERE.txt`와 `IMPLEMENTATION_HANDOFF.md`를 최신 기능 소스 `f3e0548`과 비교하고 `feat/native-white-design-20261018`에서 적용한다. 기존 `feat/notes-drive`는 보존한다. `native-white-tokens.json`은 원본 디자인 토큰의 복사이며 구현 완료 상태를 뜻하지 않는다.

## 적용 범위

- Android: 기존 네이티브 목록·폴더·녹음·상세·설정에 흰 배경, 절제된 보라색, 간결한 제목/날짜 행과 충분한 터치 영역을 적용한다. 기존 녹음 서비스, 저장소, Google 연결과 결과 읽기 계약은 유지한다.
- Windows: 기존 Avalonia 앱을 폴더/녹음/상세 3열로 정돈하고 실제 가져오기·작업 큐·모델 설정·폴더 이동·휴지통·ZIP 동작에 연결한다.
- 기존 데이터 모델을 디자인 때문에 변경하지 않는다. 시안의 샘플 결과나 성공 상태를 실제 결과로 표시하지 않는다.

## 별도 기능 범위

Android 다중 선택·휴지통과 폰 자체 전사/노트는 이번 기본 디자인 적용에 포함하지 않는다. 현재 목록 숨기기는 원본 보존 의미를 유지한다.

Windows 엔진은 이전 기능 프리뷰의 로컬 CLI 구현을 유지한다. 이번 화면 적용은 엔진 이식이나 GPU/ARM64 실행 검증이 아니다. 직접 Google OAuth, 자동 제목, 긴 전사문 노트 분할 등 이전 미구현 기능은 시안만으로 활성화하지 않는다. 실제 지원 상태는 [기능 프리뷰 기록](../FUNCTIONAL_PREVIEW.md)을 함께 참고한다.

## 검증 원칙

빌드/단위 검사와 실제 화면·입력 검증을 분리한다. 360dp/600dp·큰 글자, Windows 980×540 및 DPI, TalkBack/Narrator 검증은 실행 증거가 있을 때만 완료로 표시한다. 화면 제어 연결 실패는 우회 자동화를 사용하지 않고 미검증으로 남긴다. 설치 시 동일 Android 패키지/서명으로 갱신하며 사용자 데이터·인증정보를 지우지 않는다.

## Android 적용 결과

`0.1.3-native-white`(versionCode4)는 현재 폴더 제목을 상단에 배치하고 전체/미분류 다음에 폴더 섹션, 한 줄 제목과 우측 날짜, 하단 흰 배경의 녹음 액션을 사용한다. 정상 완료 항목은 간결하게 표시하며 진행·대기·오류는 별도 상태 문구로 유지한다. 관리 시트24dp, 클릭 영역48dp 이상, 큰 글꼴에서 한 열 전환을 소스에 반영했다.

API36 테스트 에뮬레이터에 기존 패키지를 업데이트했고, 저장된 녹음·메타데이터·결과·폴더 파일4개는 설치 전후 SHA-256이 동일했다. 이는 실제 화면/입력 검증을 대신하지 않는다. 계측 테스트 선택자는 새 라벨에 맞춰 갱신하되 UI 계측은 실행하지 않았다.

## 초기 적용의 기능 보존 확인

초기 0.1.3 적용에서 UI와 별개인 Android 녹음/동기화 코어·서비스/Google 연결, Windows 코어/설치 도구, Mac 관련 소스149개를 기준 커밋과 비교했으며 변경이 없었다. UI 핸들러는 별도로 검토한다. 이 파일 해시 검사는 모든 사용자 시나리오의 실행 성공을 뜻하지 않는다.

## Windows 연결과 시안의 차이

기존 Avalonia 화면을 220/310/나머지 폭의 3열, 흰 상세 배경, 라벤더 선택, 둥근 버튼으로 적용한다. 제목·전사·노트 검색, 다중 선택 작업 메뉴, 제목/날짜 인라인 편집, 큐 상태와 실제 오류, 모델 파일/실행 파일·입출력 폴더 설정을 기존 코어에 연결한다. 설정은 기존 모달 창 구조를 유지하며 시안의 오른쪽 패널과 다르다.

시안의 재생 막대·정렬 타임스탬프·리치 노트 근거 탐색·텍스트 형식별 내보내기·폴더 접기 등은 현재 Windows 기능 프리뷰에 모두 구현된 것이 아니다. 이번에는 지원하지 않는 액션을 모의로 활성화하지 않는다. 노트는 실제 Markdown 원문으로 표시하며 기존 ZIP 내보내기와 모바일 결과 게시를 유지한다. 검색 범위는 실제 제목/전사/노트이며, 일치하는 목록만 표시한다.

Windows 선택 행은 라벤더 단색과 체크 표시를 함께 사용한다. 빈 상세 영역의 F6 이동 대상과 긴 대화상자/진단 문구 스크롤을 독립 검토 후 수정했다. Release 빌드와 코어65·모델 설치 도구12 테스트는 통과했다. 이 결과는 macOS 호스트의 빌드/테스트이며 새 UI의 Windows 실행 증거가 아니다.

## Android 상세 화면 보완 (0.1.5-native-white)

초기 적용은 상세·녹음·설정의 기존 큰 버튼과 화면 구성을 일부 유지했다. 이번 보완은 A Native White의 중앙 제목, 좌측 뒤로가기, 상세 더보기, 라이브러리 전용 하단 녹음 액션을 반영한다. 상세 화면은 실제 제목/날짜/폴더와 작은 재생·공유 버튼, 전사/노트 탭으로 구성한다. 이동·복사·숨김·복구·수동 재시도는 더보기에서 기존 동작으로 연결한다. 노트는 실제 Markdown의 제목과 불릿을 표시하며 결과나 타임스탬프를 만들어 넣지 않는다.

녹음 화면은 흰 배경의 중앙 타이머, 원형 일시정지/재개·완료 버튼을 사용한다. 파형은 MediaRecorder의 실제 maxAmplitude를 읽으며 입력이 없을 때 가짜 파형을 표시하지 않는다. 이 단계에서는 RecordingService에 일시적인 계측 값만 추가했고 저장 형식·녹음 상태 전이·동기화 계약은 유지했다. 화면 재진입 시 파형 이력은 초기화한다.

설정은 녹음 모드·저장 위치·연결 그룹으로 정리한다. 실제 Google/Nextcloud 연결 양식은 접힌 고급 설정에서 열며 인증·연결 해제·폴더 선택 기능을 유지한다. Android 자체 AI·다중 선택·휴지통 확장은 여전히 별도 범위다.

0.1.4부터 승인된 라벤더 V 파형 PNG를 헤더/런처에 사용하고, 수동 동기화는 목록 헤더의 48dp 터치 영역을 가진 작은 새로고침 아이콘으로 제공한다. 자동 동기화 스케줄과 수동 동기화의 기존 의미는 유지한다.

최종 소스의 APK 빌드·단위 검사 51개·lint·계측 테스트 APK 컴파일을 확인했다. lint 오류는 0개이며 경고 23개가 남아 있다. 독립 검토에서 발견한 설정 상태 갱신 누락은 입력 폼을 재생성하지 않고 요약과 취소 행만 갱신하도록 보완했다. 파형 UI 갱신도 화면이 가려지거나 Activity가 일시 중지될 때 멈추도록 했다. 실제 화면 자동화는 CUA의 `Sky Computer Use native pipe startup failed` 오류로 실행하지 못했다. 따라서 A 시안과의 픽셀 일치, 큰 글꼴·가로 화면·TalkBack 및 실제 녹음 계측 동작은 소스 검토와 구분해 미검증으로 남긴다. Windows UI/엔진은 이번 보완에서 변경하지 않았다.

API 36의 `emulator-5554`에 versionCode 6을 업데이트 설치했다. 설치 전후 녹음·결과·라이브러리 파일 5개는 모두 동일했으며 데이터 초기화나 복원은 하지 않았다.

## Android 공통 대화상자 (0.1.6-native-white)

앱이 만드는 안내·오류·입력·확인·선택 창은 흰색 24dp 라운드 박스와 기존 보라색 버튼을 공유한다. 기본 녹음 모드와 Google 처리기 폴더 선택도 동일한 공통 창으로 연결했다. 최대 폭 480dp, 좌우 여백 20dp, 긴 내용 스크롤과 키보드 높이 조정을 유지한다. 권한 요청·시스템 폴더 선택·공유·시스템 Toast는 Android가 표시하는 UI다. 이번 변경은 앱 소유 대화상자에 한정한다.

## Android 재생 컨트롤 (0.1.7-native-white)

상세에서 녹음 듣기를 누르면 실제 MediaPlayer 재생 위치와 전체 길이를 표시하는 탐색 바가 나타난다. 10초 뒤로·재생/일시정지·10초 앞으로는 접근성 설명을 가진 아이콘 버튼으로 제공한다. 일시정지는 현재 위치를 유지하고 끝까지 재생한 후에는 처음부터 다시 들을 수 있다. 최초 표시 때 180ms 등장 효과를 적용하며 시스템 애니메이션 비활성 설정을 따른다. 다른 녹음/화면으로 이동하거나 앱이 배경으로 가면 기존 정책대로 플레이어를 해제한다. 동기화 화살표 벡터 경로와 48dp 버튼 안의 중앙 배치를 함께 조정했다.

### 재생 시작 오류 수정 (0.1.8-native-white)

재생 패널의 `LinearLayout.apply` 안에서 `handler`가 Activity 필드 대신 미부착 View의 null handler로 해석되어, 재생 직후 패널 생성 예외와 플레이어 해제가 발생했다. Activity handler를 명시하도록 수정했다. 이전 단위 검사·정적 검토는 이 UI 생성 경로를 검증하지 못했다. 컴파일된 호출 대상을 별도로 확인하며 실제 터치/재생 검증과 구분한다. 테스트 에뮬레이터에는 ‘재생 테스트 · 한국어 안내 35초’ 합성 AAC를 RECORD_ONLY로 추가했다.

0.1.8 설치 후 사용자가 실제 재생됨을 확인했다. 이어진 0.1.9 보완은 탐색 바의 좌우 여백을 줄이고 트랙 4dp·thumb 12dp로 표시하며, 조작 아이콘은 18/20dp로 줄였다. 흰 버튼 배경은 제거하고 48dp 터치 영역과 네이티브 탐색 접근성은 유지한다.

### 폴더 접기 및 재생 바 높이 (0.1.10-native-white)

하위 폴더가 있는 항목 옆의 독립된 화살표로 하위 트리를 접고 펼친다. 폴더 이름 영역은 기존 직접 소속 녹음 선택·길게 누르기·드래그 대상으로 유지한다. 접힌 ID는 로컬 preferences에 저장해 재실행 시 복원하며 삭제된 ID는 무시한다. 접기는 선택 폴더나 녹음 배정을 변경하지 않으므로 선택 중인 자식 폴더를 접어 숨겨도 현재 녹음 목록은 유지한다. 재생 트랙 두께는 8dp, 탐색 영역 최소 높이는 56dp로 늘렸다.
