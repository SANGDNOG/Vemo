# Galaxy ↔ Mac Google Drive 연결

개발판 Mac build 27과 Android Vemo의 연결 안내다. Windows 작업과는 별개다.

## 연결 방식
Galaxy Vemo → Google Drive → Mac Vemo에서 전사·제목·노트 생성 → Google Drive → Galaxy Vemo에서 결과 확인.

자동 왕복에는 **Mac Vemo의 Google 직접 연결**을 사용한다. Mac용 Google Drive 앱 설치는 필요하지 않다. Android가 사용하는 drive.file 권한은 앱이 만들거나 허용받은 파일로 제한되므로, Drive 데스크톱 앱에서 임의로 만든 processor.json/result.json이 같은 폴더에 있다는 이유만으로 Android에서 접근 가능하다고 보장할 수 없다. 일반 입력 폴더·ZIP 저장 폴더와 이 연결을 혼동하지 않는다.

## Mac 설정
1. Vemo 설정 → **Galaxy · Google Drive 연결**을 연다.
2. 기존 연결이 있으면 같은 계정·전용 폴더를 그대로 복원한다. Keychain 접근 복구가 표시되면 macOS 요청을 직접 승인한다. 연결 해제나 새 계정으로 교체할 필요는 없다.
3. 처음 연결하는 개발 환경이라면 같은 Google Cloud 프로젝트의 Desktop OAuth JSON을 가져오고 Google 연결을 승인한다. JSON/토큰을 GitHub나 대화에 올리지 않는다.
4. Mac 처리기를 연결하고 처리 일시정지를 해제한다. 선택한 전사·노트 모델을 준비한다. 전원 연결만 처리하도록 설정되어 있다면 전원을 연결한다.
5. Mac이 만든 **Vemo 테스트** 전용 폴더를 사용한다. 폴더 이름만 같은 별도 폴더를 만들지 않는다.

## Galaxy 설정
1. Vemo 설정 → Google Drive에서 Mac과 같은 계정으로 로그인/승인한다.
2. Mac이 만든 처리기 폴더를 선택한다.
3. 녹음 모드를 **PC 자동 처리**로 지정하고 녹음을 **완료**한다. 일시정지만 한 녹음은 업로드 대상이 아니다.
4. 앱의 자동 동기화를 기다리거나 새로고침으로 확인한다. Mac이 켜져 있고 모델 처리 조건을 충족해야 전사·노트가 생성된다.
5. Mac이 전사와 노트를 모두 완료한 뒤 결과를 Google에 게시하면 Galaxy에서 확인한다.

Mac은 처리기 연결 중 약30초마다 원격 녹음과 결과를 확인한다. Android 백그라운드 시점은 Android의 작업 스케줄에 영향을 받으며 즉시 도착을 보장하지 않는다. Mac이 잠자거나 꺼져 있으면 원본은 남고 처리는 기다린다.

## 보존과 오류
- 계정/폴더/처리기 식별자와 오디오 해시를 검증한다. 기존 연결이 다르면 임의로 덮어쓰거나 다른 처리기에 보내지 않는다.
- 녹음일은 휴대폰이 기록한 날짜와 시간대를 유지한다.
- 동기화 실패 시 원본과 이전 결과를 보존한다. 인증은 재승인하고, 폴더/처리기 불일치는 기존 연결을 확인한다.
- Android 내부 분류 폴더는 현재 Mac과 자동으로 같은 분류 구조가 되는 기능이 아니다.
- 녹음만 모드는 자동 전사 요청을 만들지 않는다.

## 이번 확인
Mac build26을 기존 고정 서명으로 빌드·검증하고 ~/Applications/Vemo.app에 설치했다. 이전build24는 별도 앱으로 보존했고 설치 과정에서 사용자 데이터 폴더를 변경하지 않았다. 두 앱의 designated requirement가 동일함을 확인했다.

Google 파일 처리 합성 검사15개와 OAuth 검사43개 통과. 일반 swift test는 현재 CLT 환경에 XCTest가 없어 실패했으며 저장소의 독립 컴파일 검사 스크립트를 사용했다. 실제 클라우드·AI 전체 왕복 통과와 구분한다.

이전 기록에는 Android 실제 Google 업로드와 로컬 전달을 이용한 Mac AI 처리/Android 결과 읽기 성공이 있지만, Mac Keychain 접근 거부로 Google를 포함한 전체 AI 왕복은 완료되지 않았다. 화면 제어 도구의 native pipe 연결 오류 때문에 보안 승인·화면 상태는 사용자 확인이 필요하다.

설치 앱과 별도 Google 프리뷰는 저장소가 다르다. 이번 파일 존재 여부 점검에서 프리뷰에는 OAuth 설정·연결 기록이 있었지만, 설치 앱의 기존 VoiceMemoTranscriber 저장소에는 없었다. 따라서 설치 앱에는 최초 연결이 필요하다. 프리뷰의 토큰·Keychain 권한·폴더 연결 기록을 임의로 복사하지 않는다. Mac에서 최초 연결한 뒤 Android도 해당 처리기 폴더를 선택하고 새 테스트 녹음으로 실제 결과 도착을 확인해야 한다. 기존 녹음은 이전 폴더 연결을 유지하므로 새 연결로 자동 이관된다고 가정하지 않는다.

## build 27 변경
- 상단의 중복 파일 가져오기·설정 버튼을 제거했다. 설정은 가장 왼쪽 폴더 사이드바 하단에 고정하고, 녹음 목록의 + 가져오기와 ⌘O는 유지한다.
- 시작 시 연결 복원에 일시적인 서버·네트워크 오류가 발생하면 최소 30초 간격으로 다음 자동 확인에서 복원을 다시 시도한다. 성공 후에는 반복하지 않는다. 인증·Keychain·계정/폴더 불일치는 자동 재승인하지 않는다.
- 사용자의 연결/연결 해제 작업과 취소·종료는 이전 복원 재시도를 이어서 실행하지 않도록 처리한다.
- 빌드·서명 검증과 연결 복원 회귀 검사179개가 통과했다. 수정 전 소스로 동일 검사를 실행하면 복원 재시도 관련26개가 실패한다. 합성 I/O 검사이며 실제 계정 왕복을 뜻하지 않는다.
- 새 빌드는 별도 경로에 준비한다. 실행 중인 build 26을 정상 종료한 뒤 설치하며, 화면 확인과 실제 Google AI 왕복은 별도 검증 항목이다.
