# Android–Windows Google Drive 왕복 검증 (2026-10-18)

Windows 0.1.10-google-sync와 Android API 36 에뮬레이터의 0.1.13-native-white로 실제 Google Drive 왕복을 확인했다. Mac·Android 디자인 소스는 수정하지 않았다.

## 실제 확인한 흐름

- Android가 이전 Mac 처리 폴더를 사용하고 있어 앱의 Google 폴더 선택 화면에서 Windows 테스트 폴더로 연결했다. 기존 녹음별 연결은 변경하지 않았다.
- 기존 35초 한국어 합성 음성을 새 테스트 녹음으로 에뮬레이터에 준비했다. 최초 업로드는 앱의 수동 확인 버튼으로 시작했다. 이번 시험은 마이크 녹음 시작/종료 시험이 아니다.
- 실행 중인 Windows 앱이 자동으로 수집하고 실제 Whisper/llama 엔진으로 전사·노트를 생성했다. 처음에는 결과 게시가 이전 테스트 항목의 충돌 때문에 막혔다.
- 수정 빌드에서 충돌 항목을 그대로 두고 새 결과가 게시됐으며 Android의 전사·노트 화면에 표시됐다. 결과 수신 시 별도 수동 새로고침은 누르지 않았다.
- 녹음 ID·처리기 ID·원래 날짜 문자열·오디오 SHA-256·전사와 노트 내용이 일치했다. Windows 항목은 반복 스캔 뒤에도 1개였으며 ZIP은 original.m4a, transcript.txt, notes.md만 포함했다.
- 녹음이 진행 중이지 않은 상태에서 Android 프로세스를 재시작하고 저장된 결과의 동일성을 다시 확인했다.

## 수정과 검증

완료 항목의 알려진 개별 게시 오류를 기록한 뒤 나머지 항목을 처리한다. 마지막에는 기존 오류를 다시 전달하므로 부분 실패를 성공으로 숨기지 않는다. ETag가 없는 충돌 결과를 덮어쓰지 않으며 인증·계정·루트·네트워크·취소 오류는 즉시 전달한다.

Core 테스트: 189 통과, Windows DPAPI 전용 1 제외. 수정 전 실패/수정 후 통과 회귀 테스트는 첫 항목 충돌, 후속 게시, 반복 시 중복 방지, 취소 및 전역 오류 전달을 포함한다. 독립 코드 리뷰에서도 차단 문제는 발견되지 않았다. 배포 DLL 해시는 설치본과 일치한다.

## 범위와 남은 제한

긴 개인 녹음은 사용하지 않았다. 14,000자 초과 노트, 실제 Galaxy 마이크·백그라운드 절전, 처음 녹음 완료 시 자동 업로드는 이번 시험 범위 밖이다. 전사에는 일부 인식 오류가 있어 결과 전송의 정확성과 음성 인식 품질을 구분해야 한다.

기존 충돌 결과 자체는 보존하며 경고가 남는다. ETag 없는 기존 결과 갱신, 수집 단계의 잘못된 요청이 배치를 막는 경우, Android/Windows의 시간 소수 자릿수·최대 파일 크기 차이는 별도 개선 대상이다. OAuth는 결과 JSON을 전달하며 ZIP 클라우드 업로드와는 별개다.

로컬 증거: `local-validation/android-windows-roundtrip/`의 acceptance.json, android-restart.json, core-tests.log, UI 캡처, 독립 리뷰. 인증정보는 기록·커밋하지 않았다.
