# Windows Google Drive 연결과 Native White 설정

Windows 전용 브랜치에서 기존 라이브러리를 유지하며 설정을 오른쪽 패널에 통합했습니다. Google 연결은 Drive 데스크톱 앱의 로컬 폴더와 별개입니다.

## 직접 OAuth 연결

1. 설정 → Google Drive → **Google Drive 연결**을 누릅니다.
2. 브라우저에서 Google 계정으로 로그인하고 권한을 승인합니다.
3. 이 PC용 Vemo 폴더를 선택하거나 새로 만듭니다. 다른 PC·Mac의 폴더는 기존 연결을 보호하기 위해 선택 목록에서 제외합니다.
4. Android에서도 같은 계정과 **이 Windows PC용 폴더**를 선택합니다. 완료된 녹음은 PC로 가져오고 전사·노트 결과는 휴대폰으로 동기화합니다.

연결 후에는 자동으로 동기화합니다. 수동 갱신도 사용할 수 있습니다. 사용자가 Google Cloud 프로젝트를 만들거나 OAuth JSON을 발급·가져올 필요는 없습니다.

다른 PC가 소유한 폴더에는 게시하지 않습니다. 현재 바인딩은 계정·폴더·처리기에 고정되며 연결 해제는 로컬 로그인 토큰을 삭제하고 기존 데이터·바인딩은 보존합니다. 임의의 Drive 폴더 전체를 검색/수집하지 않습니다. 재승인은 동일 계정으로 진행합니다. Google 프로젝트가 테스트 모드이면 등록된 테스트 사용자만 사용할 수 있고 재승인이 필요할 수 있습니다.

배포 앱에는 개발자가 등록한 데스크톱 OAuth 클라이언트 구성이 포함됩니다. 개인 로그인 토큰은 포함하지 않으며, 로그인 후 갱신 토큰은 Windows 현재 사용자 DPAPI로 보호합니다. 권한 승인은 사용자가 Google 화면에서 진행합니다.

## 저장 위치 구분

- 오디오 입력 폴더: 최상위의 안정화된 로컬 오디오 파일을 자동 가져오기. 다운로드 중 placeholder는 대기합니다. 파일 수정일을 녹음 날짜로 추정하지 않습니다.
- 모바일 v1 로컬 동기화 폴더: 기존 파일 규약을 지원하는 별도 폴더 연동입니다.
- ZIP 저장 폴더: 원본·전사 TXT·노트 MD 세 파일을 녹음별로 저장하며 Vemo 논리 폴더를 반영합니다. Google OAuth 결과 게시와 별개입니다. **OAuth가 ZIP까지 업로드하지는 않습니다.** Drive 데스크톱 동기화 폴더를 ZIP 위치로 선택할 수 있습니다.

## 화면과 기능

설정의 그룹형 카드·고급 모델 설정 접기, 폴더 관리/접기/이동, 작은 가져오기 버튼, 읽기용 노트, 결과 복사/내보내기, Windows 오디오 재생/탐색, 입력 폴더 감시, 자동 ZIP·전원 정책, 시작 프로그램·지원되는 환경의 트레이 옵션을 연결했습니다. 기존 녹음·모델·드래그 기능을 유지합니다.

## 검증 범위

실제 Avalonia 화면을 1280×820과 980×540으로 렌더했습니다. Windows UI 자동 검사와 실제 M4A 전사·노트·ZIP 처리, 네이티브 DPAPI 저장을 검증했습니다. 테스트 서버의 OAuth/Drive 경합·변조·중복·취소 검사는 실제 계정 승인/왕복 동기화 성공을 대신하지 않습니다. 2026-10-18에는 사용자 승인 계정으로 별도 Windows 테스트 폴더 생성, 합성 녹음 가져오기, 시험 전사·노트 결과 게시/재다운로드와 반복 동기화를 확인했습니다. 2026-10-18 후속 검증에서는 Android 에뮬레이터에 준비한 35초 합성 음성을 앱에서 업로드하고, Windows의 실제 모델 처리 결과를 Android에서 수신·표시했습니다. 첫 녹음 자동 업로드와 실제 Galaxy 마이크/절전 동작은 별도 검증 대상입니다. 상세 범위와 게시 충돌 수정은 WINDOWS_ANDROID_ROUNDTRIP.md를 참고하세요. 실제 물리 마우스/Windows 화면 배율/Narrator/오디오 장치 출력은 별도 확인이 필요합니다.

아직 계획 전체와 동등하지 않은 항목: 앱 내부 모델 다운로드·재개, 자동 제목 재생성, 14,000자 초과 전사 노트 합성, 시간 정렬/자막 내보내기, 키워드 필터와 인용 seek. 지원하지 않는 기능을 작동하는 버튼으로 표시하지 않습니다. 최신 세부 검증은 WINDOWS_PLAN_AUDIT.md와 작업 기록을 참고하세요.

## 배포 담당자

Google Cloud 프로젝트와 Desktop OAuth 클라이언트 등록은 Vemo 개발자가 관리합니다. 테스트 모드에서는 등록된 테스트 사용자만 로그인할 수 있으므로 일반 공개 전 동의 화면의 게시 상태·브랜딩·필요한 검증을 개발자가 준비해야 합니다. 이 작업은 사용자마다 반복하지 않습니다.

배포 시 `windows/scripts/publish.py --google-client-json /absolute/private/desktop-oauth.json ...`을 전달합니다. 빌드는 installed 형식만 허용하고 필요한 데스크톱 클라이언트 정보만 리소스에 포함합니다. 개인 계정 토큰·서비스 계정 키를 사용하지 않습니다. 원본 파일은 체크아웃 외부에 보관합니다. 구성 없는 개발 빌드는 연결을 사용할 수 없다고 표시합니다.
