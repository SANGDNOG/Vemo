# Native app ↔ local engine protocol v1

Binding shared contract for the two implementation owners. User authorized implementation on 2026-10-11. Both sides use snake_case JSON keys. JSONL UTF-8, one event per line, line <=8MiB. stdout is JSON only; stderr has no recording content. Engine CLI: `python -m voice_memo_transcriber.service --state-root PATH --model-root PATH [--ffmpeg-path PATH]`.

Commands: `{request_id: string, protocol_version: 1, kind: string, payload: object}`. Events: `{sequence: integer, protocol_version: 1, kind: string, payload: object}`. `command_result` additionally carries payload `{request_id, ok, error?}`. hello and snapshot return `snapshot` payload `{jobs: [Job], engine_status: object}`. All mutation responses are idempotent by request_id.

Kinds: hello, snapshot, discover, import, enqueue, backfill, snapshot_ready, pause, resume, retry, retitle, generate_notes, set_recording_date, publish_ack, shutdown, download_models, set_policy, trash_recording, restore_recording, refresh_recording. discover payload `{memos:[Memo]}`. import payload `{memo:Memo}`; an explicit import is queued, even on initial baseline. enqueue/backfill payload `{uuids:[string]}`. retry/retitle/set_recording_date payload includes `job_id`; retitle uses `{topic:string}` for manual topic or `{generate:true}` for regeneration; set_recording_date uses `{recording_date:"YYYY-MM-DD"}` and provenance user_supplied. `generate_notes` uses `{job_id}` and reuses the owned transcript; it must not re-run ASR. Notes are automatic for new jobs. The native coordinator also requests missing pending notes on settled legacy jobs; failed generation requires an explicit retry. pause/resume are global. set_policy payload `{ac_only:bool}` persists automatic power policy (default true), independently of manual pause. engine_status carries `ac_only`. Native sends policy before hello/discovery/import so no job starts under a stale setting; engine also checks actual AC power before processing when enabled.

Successful pause, resume and set_policy commands emit `engine_status` with the committed current model/policy state before `command_result`, so controls update without reconnecting. Replaying a successful request emits the current status without applying the mutation again. Rejected commands emit no success status.

Memo fields: uuid, recorded_at (ISO8601 timezone-aware string|null), recorded_at_source, original_timezone|null, duration_s|null, media_revision {size,mtime_ns}|null, completion_evidence (finished|active|unknown), source_kind (voice_memos|import), source_reference (stable opaque native registry ID), original_title|null, metadata_revision (string|null) (optional Apple metadata version). Last nonnull media and metadata revisions survive unavailable scans. Private source paths must not be sent to the engine. Unclear completion evidence remains waiting; imports are explicitly finished after stable copy/decoding.

Job fields: id, uuid, topic|null, recording_date|null, recorded_at|null, duration_s|null, status, wait_reason|null, stage, completed_units|null, total_units|null, elapsed_seconds, artifact_path|null, audio_path|null, pcm_path|null, error|null, title_status, alignment_status, original_title|null, notes_path|null, notes_status|null, notes_error|null, deleted_at|null, refresh_pending (bool). Optional notes fields are absent on legacy jobs. artifact_path is the engine-owned transcript JSON `{text,segments:[{start_s,end_s,text}],alignment_status}`. audio_path is an owned snapshot, never private source; pcm_path is the prepared owned mono16k WAV, optional for older jobs. QTA playback uses this PCM after native owned-path validation; other formats retain original snapshot playback. UI sentence/paragraph projection preserves authoritative text and raw alignment segments. Status values: unprocessed, waiting, preparing, transcribing, aligning, titling, noting, saving, completed, needs_recording_date, failed, paused. job_changed payload `{job:Job}`.

snapshot_requested payload `{job_id,source_reference,snapshot_request_id}`. Native checks source before/after device, inode, size and nanosecond modification/change stamps while copying, then reports the actual owned-copy revision pair (equal once stable; source stamps remain private). Engine compares these stamps to the owned file. Native sends snapshot_ready payload `{job_id,snapshot_request_id,owned_path,revision_before:{size,mtime_ns},revision_after:{size,mtime_ns}}`. Engine validates path inside state root and hashes normalized PCM. Source-copy failures use snapshot_ready payload `{job_id,snapshot_request_id,error:{code,message,recoverable}}` instead of a path.

publication_ready payload `{job_id,publication_id,manifest_path}`. Manifest `{schema_version:1,publication_id,job_id,uuid,recording_date,title,revision,files:[{name,path,sha256}]}`. Each path belongs to engine artifact root. Native publisher verifies source hashes and existing output manifest publication_id + all hashes; exact prior publication returns the same receipt without rewriting. New immutable revisions live under output/YYYY/MM/UUID/versions/<publication_id>/ and a manifest.json in UUID root is atomically activated. Finder/result-folder action opens active revision folder so Files shows normal TXT/MD files. Previous immutable revisions remain. No symlinks or partial root file set is authoritative.

publish_ack payload `{job_id,publication_id,receipt:{publication_id,output_manifest_path,artifact_hashes}}`, or `{job_id,publication_id,error:{code,message,recoverable}}`. Only successful validated ACK transitions engine job to completed. Engine replays publication_ready after crash; native detects existing exact output. Conflicts preserve user output and local artifacts. Timestamped filenames apply within every revision directory.

Model dirs inside model-root: asr/ for Qwen/Qwen3-ASR-1.7B, aligner/ for Qwen/Qwen3-ForcedAligner-0.6B, title/ for mlx-community/Qwen3-4B-Instruct-2507-4bit. models.json pins downloaded revisions. download_models launches explicit bootstrap download and emits `model_progress` payload `{model,downloaded_bytes,total_bytes|null,state,error?}`; no fake download percent. engine_status carries models_ready, model_status and paused. Operational inference uses local paths + offline/cache-only mode; never auto-download from ASR/title worker.

App runtime is ~/Library/Application Support/VoiceMemoTranscriber/runtime/bin/python3; scripts/install-runtime.sh builds and installs a noneditable project wheel into that runtime; scripts/build-app.sh builds only the native app. The app never starts the system Python by fallback. ffmpeg defaults /opt/homebrew/bin/ffmpeg. State root is App Support/VoiceMemoTranscriber; model-root is its models/. A single native app and engine writer operate; app crash triggers independent engine EOF/parent supervisor and model process group cleanup. Reopening a running app activates its GUI; restart starts a new engine/session from DB.

## Local notes (optional backward-compatible fields)

`notes_path` points to an owned JSON artifact: `{schema_version:1, source_sha256, summary:[{text,quotes:[string]}], highlights:[{quote}], topics:[{keyword,summary,quotes:[string]}]}`. Hash is SHA-256 of the UTF-8 authoritative transcript text. All nonempty quotes must be exact source substrings, maximum 600 characters. Summary/topic text is capped at 1000 characters; keywords at 80. Invalid citations are discarded. A source hash mismatch is rejected by native projection.

Notes use the existing title model. Long input is processed in bounded source chunks with committed checkpoints. `notes_status` reports pending/completed/failed and `notes_error` is separate from transcript errors. A note failure must preserve successful transcription, previously valid notes and output versions. Successful notes add separate dated note Markdown and JSON files to the publication manifest; the manifest identity incorporates notes content so new notes produce new immutable output.

## Shared Drive folders

Native selects a user-owned local input and output folder; paths don't enter Python source references. File availability metadata and `SF_DATALESS` are checked before opening audio. Non-downloaded files wait; iCloud downloads may be requested via Foundation, other providers require offline availability. Folder scan imports each stable decoded file independently and records invalid revisions until they change. Input and output must be separate non-overlapping canonical folders. Provider upload status is outside the protocol; `publish_ack` confirms local durable output only.


`trash_recording`, `restore_recording`, and `refresh_recording` use `{job_id}`. Trash is durable and recoverable within Vemo: originals, owned snapshots, transcripts, notes, and previously exported files are retained. Snapshot events include trashed jobs; normal UI lists, automatic processing, and new exports exclude them. Discovery never resurrects them. Restore resumes interrupted work or retains completed results, checking changed sources first.

A refresh snapshots the latest available source and compares normalized PCM. Identical PCM retains committed model results; changed PCM restarts transcription and automatic notes. Generation identity and `snapshot_request_id` reject pre-refresh, pre-trash, and pre-restart callbacks. Native echoes the token on both success and error. Manual title edits on idle unprocessed recordings remain manual through transcription and source refresh.

Individual ZIP export is native-only. `PerRecordingZIPStore` validates a settled, nontrashed recording and notes matched to its transcript. Each ZIP contains exactly `original.<extension>`, `transcript.txt`, and `notes.md`. Private durable receipts under `native/recording-zips` bind destination, recording, content, and archive hashes. Unchanged verified content is reused; new content creates an immutable ZIP version without overwriting prior files. The automatic coordinator retries unavailable destinations with a delay, respects automatic ZIP opt-out, and cancels an in-flight archive if its recording changes eligibility before publication. Server upload remains the external Drive client's responsibility.

Visible ZIP filenames use the sanitized recording title including its recording-date suffix, bounded to 120 UTF-8 bytes while preserving that suffix. Occupied names receive ` (2)`, ` (3)`, etc. Content fingerprints remain in private receipts, not visible filenames; publication never overwrites an existing destination file.

`purge_recording` uses `{job_id}` and requires a trashed recording. The engine first commits a purge intent, then deletes only that job's owned work, artifacts, snapshots and matching import cache. It preserves external sources and exported files. A minimal persistent tombstone suppresses rediscovery and stale callbacks. Success emits `job_removed {job_id}` before `command_result`; completed tombstones are omitted from snapshots. Cleanup failure returns recoverable `purge_cleanup_failed`, keeps the trashed job visible with optional `purge_pending: true`, and disallows restore. A new purge request or restart retries committed cleanup. Schema-one import entries support optional `purged: true`; native import delivery, matching-hash reimport and snapshot creation respect this flag and the shared registry lock.

Multi-selection is native UI state. Bulk actions capture the selected IDs, revalidate eligibility and send individual lifecycle commands; they are not an atomic multi-job engine transaction. Folder assignment uses the library store's existing atomic multi-ID operation. Drag sessions bind a captured selection to the existing session/drag identity.
